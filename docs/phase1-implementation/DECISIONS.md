# Phase 1 decisions

Every open product or architecture question raised by the six planning agents, numbered once (PD-nn). Each entry gives
the options, the recommendation, and where it came from. **Nothing here is decided until the product owner or head of
tech approves it**; the status column records that. Accepted Phase 0 decisions stay in `docs/DECISIONS.md`.

Status values: `OPEN` (needs an answer), `PROPOSED` (recommendation ready, needs sign-off), `APPROVED`, `REJECTED`.
Draft references: architect `D-n`, backend `Qn`, devops `Qn`, desktop/CLI `Qn`, frontend `Qn`, QA `Q-nn` (each in
`_drafts/<agent>.md`).

## Conflicts between the planning drafts (resolved here, pending approval)

| Topic | Drafts disagree | Consolidated position |
|---|---|---|
| Viewer host | Frontend: viewers on `zaa.gl/p|i|f`. Architect: viewers on `app.zaa.gl`. Backend: `app.zaa.gl/v/{code}`. | Architect's (PD-02). |
| Link-to-content model | Backend offered LO-A/B/C and preferred a hybrid; architect chose option (a). | Option (a): every share is a Link with `target_kind` + `resource_id`; resources also carry an opaque `public_id` for signed delivery URLs (backend's hybrid detail kept). |
| Upload host | Architect: `api.zaa.gl` chunked. DevOps: `dl.<ucd>`. | Open (PD-12). |
| Markdown | Backend: Markdig + HtmlSanitizer. Frontend: `react-markdown`. | Open, recommendation frontend (PD-09). |
| Burn timing | Architect: at grant issue, ~10 min. Backend: at first ticket GET, 30 min resume. | Backend's precise version (PD-05). |
| Diff | Frontend: `react-diff-viewer-continued` in the tech stack, but proposes rendering the backend's DiffPlex output. | Backend DiffPlex computes, frontend renders its own component. |
| Uploader library | Tech stack: Uppy + tus. Frontend: `tus-js-client` directly. | `tus-js-client` with our own MUI UI (smaller bundle); record as a tech-stack deviation once approved. |
